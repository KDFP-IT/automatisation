# КДФП — внутренний сервис закладок PDF

Оформление адаптировано к официальному сайту КДФП: логотип, локальные шрифты Onder/Montserrat, оранжевая и графитовая палитра. Docker-развёртывание описано в корневом `DEPLOY.md`.

Рабочий веб-интерфейс к `add_drawing_bookmarks.py`. Сотрудник выбирает PDF, ждёт обработки и скачивает копию с закладками. Python на компьютерах сотрудников не нужен — только браузер и доступ к серверу.

## Быстрый запуск на этом компьютере

В корне проекта дважды щёлкните `start-web.cmd`. Он запускает сервер и открывает `http://127.0.0.1:8080`. При первом запуске, если зависимостей нет, создаётся `.venv` и устанавливаются пакеты; для этого нужен доступ к PyPI. Нужен установленный Python, рекомендуется 3.12. На текущем компьютере также поддерживается уже установленный Python из среды Codex.

Не открывайте `webapp/static/index.html` как файл: он предназначен для работы через сервер. Стили загружаются по HTTP, и обработка PDF требует серверной части. Запускать файл нужно только на сервере; сотрудникам затем отправляют HTTP-адрес сервиса. При повторном запуске `start-web.cmd` используется уже работающий сервис. Фоновый сервер продолжает работать после закрытия окна запуска; журнал и PID находятся в `webapp/data/server.log` и `server.pid`.

## Запуск на сервере Windows

Установите Python 3.10 или новее (рекомендуется 64-битный Python 3.12). Скопируйте папку проекта целиком: нужны корневой скрипт, корневой `requirements.txt` и папка `webapp`. В PowerShell из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\webapp\requirements.txt
.\webapp\start.ps1 -BindAddress 0.0.0.0 -Port 8080
```

После запуска сотрудники открывают `http://ИМЯ-СЕРВЕРА:8080` (например, `http://pdf-tools:8080`). `0.0.0.0` — адрес привязки, его не вводят в браузере. Для проверки только на сервере используйте `start.ps1` без параметров и откройте `http://127.0.0.1:8080`.

Если политика PowerShell запрещает запуск `.ps1`, используйте напрямую:

```powershell
.\.venv\Scripts\python.exe .\webapp\app.py --host 0.0.0.0 --port 8080
```

Администратору нужно разрешить входящие подключения к выбранному порту только из нужных корпоративных подсетей. Для постоянной работы настройте запуск той же команды через принятую в компании службу или планировщик при старте сервера. Рабочая папка — корень проекта. Запускайте один экземпляр сервиса на отдельной учётной записи с правами записи только в каталог данных. По умолчанию внутри него обрабатываются два файла одновременно; следующие ждут в очереди.

## Доступ сотрудников

Встроенной регистрации нет. Доступ определяется доступом к внутреннему серверу. Для корпоративной авторизации разместите сервис за IIS/nginx/другим обратным прокси с принятым в компании SSO и HTTPS. Не публикуйте этот вариант напрямую в интернете.

Скачивания привязаны к сессии браузера сотрудника; ссылка из другого браузера не откроется. Это разделение результатов, а не замена корпоративной аутентификации. В ответах нет разрешающих CORS-заголовков, загрузка требует специальный заголовок, файлы доступны только через проверенные маршруты скачивания.

## Хранение и настройки

Весь HTML, CSS и JS локальные; внешних CDN, аналитики и отправки PDF во внешние сервисы нет. Сервер хранит файлы во временных папках `webapp/data/jobs`. Входной PDF удаляется после завершения задания. PDF результата и CSV удаляются через час после завершения; очистка выполняется раз в минуту. После перезапуска сервера старые результаты недоступны, их файлы удаляются по сроку хранения (с дополнительным запасом до 5 минут). Оригинал на компьютере сотрудника не меняется.

Переменные окружения:

| Имя | Назначение |
| --- | --- |
| `PDF_WEB_DATA_DIR` | Отдельная папка для временных файлов; по умолчанию `webapp/data` |
| `PDF_WEB_SECRET` | Случайный секрет подписи cookie; без настройки генерируется при каждом запуске. Не добавляйте его в исходники. |
| `PDF_WEB_HTTPS=1` | Сессионные cookie передаются только по HTTPS; задавайте при работе через HTTPS-прокси |

Ограничения: один PDF до 200 МБ; до 2 500 страниц; не более 8 активных заданий (включая очередь); обработка одного задания до 5 минут. Каждый PDF обрабатывается отдельным процессом. Настройки находятся в `create_app()` в `app.py`. Лимит запроса на обратном прокси должен быть не меньше лимита сервиса, а тайм-аут загрузки должен позволять передачу большого файла. Отдельного дискового лимита на общий объём результатов нет: администратору следует выделить достаточно места и контролировать его заполнение.

## Правила закладок

Сохраняются содержательные разделы и их переходы. Удаляются автоматические ветки листов, выявленные скриптом. Новые названия формируются из штампов и помещаются внутрь существующей «Графической части»; если раздела нет, он создаётся. Повторная обработка заменяет наши закладки без дублей.

Распознавание настроено на штамп 185 × 55 мм с полями 5 мм. Для сканов сначала нужен OCR. Страницы без распознанного шифра/стадии пропускаются — список результата нужно сверить с перечнем чертежей, особенно для другого шаблона. При неполном распознанном штампе задание завершается ошибкой; пропуск возможен только через явную опцию. Подробности в корневом README.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s webapp -p test_app.py -v
```

Для интеграционной проверки предоставленного документа (ожидаются 239 страниц и 159 чертежей):

```powershell
$env:PDF_TEST_FILE = 'K:\!Общие документы\Программисты\Закладки чертежей\30-09 - Раздел ПД №4 Подраздел 4.pdf'
.\.venv\Scripts\python.exe -m unittest discover -s webapp -p test_app.py -v
```

Тесты проверяют загрузку и скачивание, сохранение разделов и всех страниц, отклонение неподходящих и зашифрованных файлов, сессии разных сотрудников, размер загрузки, очередь, тайм-аут и очистку файлов.
