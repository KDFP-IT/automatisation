# Офисный чат для Windows

Прототип личных сообщений для Windows x64 и ARM64. Серверу нужен Python 3.10+. Десктопный клиент работает на Electron, запуск через PowerShell.

## Запуск на одном компьютере

Выполните команды в трёх окнах PowerShell из каталога `D:\automatisation\office-chat`.

```powershell
python server.py server.demo.json
```

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-Chat.ps1 .\anna.demo.json
```

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-Chat.ps1 .\ivan.demo.json
```

При первом запуске скрипт скачивает официальный Electron и проверяет SHA-256. Сначала запустите один клиент, дождитесь загрузки, затем запустите второй. Рантайм хранится в `.electron` рядом со скриптом и используется повторно. В закрытой сети эту папку можно заранее скопировать с машины с доступом к GitHub.

Дождитесь статуса «Подключено». Сверните окно Ивана, выберите его в списке сотрудников Анны и отправьте сообщение. Поверх обычных окон в центре экрана, на котором находится указатель, откроется диалог с историей и полем ответа. Для каждого собеседника используется одно окно. Его можно свернуть или закрыть. Крестик основного окна сворачивает клиент, кнопка выхода на тёмной панели завершает процесс.

Список сотрудников берётся из конфигурации сервера. Можно искать по имени (`Ctrl+K`), фильтровать по статусу и открывать непрочитанные диалоги. Свой статус меняется в профиле внизу. Статусы относятся к локальному чату. После отключения клиент отображается как «Не в сети» с задержкой до 15 секунд. Кнопка с улыбкой открывает панель эмодзи. `Enter` отправляет сообщение, `Shift+Enter` добавляет новую строку.

## Подключение коробочного Битрикс24

1. Скопируйте `server.demo.json` в `server.local.json`. Замените ключи пользователей на реальные числовые ID сотрудников в Б24. Для каждого сотрудника задайте имя и отдельный случайный токен чата.
2. В поле `bitrix_webhook` укажите базовый URL входящего вебхука этого сотрудника с правом `im`, в виде `https://portal.example/rest/101/SECRET/`. URL хранится только в конфигурации сервера. Проверьте доступ к порталу и право сотрудника отправлять личные сообщения. [Документация метода отправки](https://apidocs.bitrix24.ru/api-reference/chats/messages/im-message-add.html).
3. Создайте каждому сотруднику свой `*.local.json` клиента на основе демофайла. Укажите `server`, `user` и `token`.
4. Запустите сервер с `server.local.json` и клиенты с их конфигурациями. Для двух разных ПК в доверенной сети поднимите HTTPS-прокси перед сервером, укажите его адрес в конфигурациях клиентов и задайте таймаут прокси больше 20 секунд. Сервер по умолчанию слушает только localhost. HTTP с демотокенами предназначен для проверки на одном компьютере.

## Доставка и история

- Сервер подтверждает отправку после записи в SQLite. Клиент держит открытым HTTP-запрос до поступления нового сообщения. Отправка в Б24 выполняется отдельно. Задержка до двух секунд — цель для подключённых клиентов, её нужно подтвердить в сети компании.
- Клиент загружает до 200 последних личных сообщений из локального журнала при запуске. При обрыве сети в пределах запущенной сессии догружает сообщения после последнего полученного ID. Сообщения, созданные в самом Б24, в клиент не импортируются.
- Файл журнала `*.sqlite3` создаётся рядом с серверным конфигом. В нём хранится переписка для локальной истории, повторной доставки и очереди выгрузки. Ограничьте доступ к файлам сервера и конфигурации.
- Статус `pending` означает ожидание записи в Б24, `archived` — подтверждённую запись с ID Б24, `review` — запись, которую нужно проверить вручную. Если Б24 ограничил запросы или отказал в соединении, сервер повторит попытку. При таймауте или другом неоднозначном результате проверьте диалог в Б24 перед повтором. Это позволяет избежать дублирования сообщения, если оно сохранилось до обрыва ответа. После проверки записи можно обновить статус в SQLite при остановленном сервере. Для подтверждённой записи укажите `archived` и `bitrix_id`. Если записи в Б24 нет, верните `pending`.
