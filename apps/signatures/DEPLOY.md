# КДФП — развёртывание проверки подписантов

## Готовый пакет для Linux x86-64

Пакет `kdfp-signature-checker-linux-amd64.zip` содержит готовый образ nginx,
приложение и скрипт установки. На сервере нужны Docker Engine и Docker Compose
с поддержкой `up --wait` (Compose 2.20+). После распаковки интернет не требуется.

Распакуйте архив и перейдите в папку `kdfp-signature-checker`:

```sh
sh deploy.sh --bind 10.0.0.25 --port 8087
```

Замените адрес на внутренний IPv4 сервера. Сотрудники открывают
`http://10.0.0.25:8087/`. Скрипт проверит контрольные суммы файлов,
загрузит готовый образ, проверит его архитектуру и версию и дождётся `healthy`.
Повторный запуск сохраняет ранее заданные адрес и порт.

Для корпоративного HTTPS-прокси на том же сервере:

```sh
sh deploy.sh --bind 127.0.0.1 --port 8087
```

По умолчанию привязка только к `127.0.0.1`. Пример для уже настроенного
корпоративного nginx, обслуживающего выделенное имя по HTTPS:

```nginx
location / {
    proxy_pass http://127.0.0.1:8087;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

DNS, сертификат, сетевой доступ и корпоративная авторизация настраиваются
администратором. Приложение поддерживает HTTPS и внутренний HTTP: для HTTP
предусмотрен локальный расчёт SHA без Web Crypto. Секреты и база данных не нужны.
Выделенный адрес в корне сайта — основной проверенный вариант размещения.

## Запуск из исходников

Пакет `kdfp-signature-checker-deploy.zip` содержит исходники и Dockerfile.
Первая сборка требует доступа к Docker Hub; базовый образ закреплён digest.

```sh
cp .env.example .env
# При необходимости измените SIGNATURE_BIND и SIGNATURE_PORT в .env
docker compose -p kdfp-signatures up -d --build --wait
```

Серверная часть — только статический nginx, без Python и Node.js.
Node.js нужен лишь для запуска тестов исходников. Основная вычислительная
нагрузка при обработке PDF приходится на браузер сотрудника.

## Существующий веб-сервер

Можно разместить только содержимое `dist/` на существующем статическом сервере.
Обязательные MIME-типы: `.mjs` и `.js` — `application/javascript`, `.json` —
`application/json`, `.css` — `text/css`, `.woff` — `font/woff`, `.ttf` — `font/ttf`.
Все файлы внутри `dist`, включая `vendor` и `assets`, должны оставаться вместе.
Открывайте страницу через HTTP/HTTPS, а не как `file://`.
Для `index.html`, JS и CSS используйте `Cache-Control: no-cache`, чтобы
после обновления сотрудники получали текущую версию приложения.

## Проверка и управление

```sh
docker compose -p kdfp-signatures ps
curl -f http://127.0.0.1:8087/healthz
docker compose -p kdfp-signatures logs --tail=50
docker compose -p kdfp-signatures down
```

`/healthz` возвращает `ok`. Контейнер работает от пользователя nginx,
без root, с файловой системой только для чтения и временным `/tmp`.
Порт внутри контейнера — 8080; на хосте по умолчанию — 8087.
Пакет образа собран только для Linux/amd64. Для ARM64 нужна отдельная сборка.

Перед обновлением сохраните нужные CSV: выбранные файлы и ручные отметки
находятся в памяти вкладки и теряются после обновления страницы.
Обновление: распаковать новый пакет в отдельную папку, перенести значения
адреса/порта из прежней `.env` и запустить `sh deploy.sh`.
Для отката запустите предыдущий сохранённый пакет теми же параметрами.

## Приёмка

1. Откройте сайт в браузере сотрудника. Должны загрузиться логотип и локальные шрифты.
2. Добавьте PDF без SIG: должен появиться список фамилий.
3. Добавьте соответствующий SIG: подпись засчитывается только в текстовой части.
4. На чертеже проверьте рукописные подписи и переход к увеличенному штампу.
5. Проверьте исправление записи и выгрузку CSV.

Файлы PDF и SIG не отправляются на сервер. В релизе нет пользовательских
документов, временных результатов, учётных данных и содержимого сертификатов.
Рабочие ограничения распознавания и проверки ЭП описаны в `README.md`.
