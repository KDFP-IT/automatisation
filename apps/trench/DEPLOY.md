# КДФП · Установка и обновление 7.3.0

Нужны Docker Engine и Docker Compose v2. В комплекте два сервиса: Nginx (порт 8086) и внутренний API Flask/Gunicorn. SQLite хранится в постоянном томе trench-data. Node.js на сервере не нужен. Во время работы интернет не используется. База общая, без аккаунтов и разграничения прав.

## Перед обновлением установленной системы

Используйте прежнюю папку установки и прежнее имя Compose-проекта: от них зависит имя тома БД. Ниже используется ~/trench — папка из предыдущей установки. Существующий .env архивом не заменяется. Если в нём указан COMPOSE_PROJECT_NAME, оставьте прежнее значение.

Если уже работает версия с БД (4.1 и новее), перед распаковкой сделайте резервную копию из прежней конфигурации:

```sh
cd ~/trench
backup_path=$(docker compose exec -T api python backup.py) && docker compose cp "api:$backup_path" "./trench-backup-$(date +%Y%m%d-%H%M%S).sqlite3"
cp compose.yaml compose.before-update.yaml
```

Если старая версия была только статической страницей, серверной БД в ней нет. Сначала экспортируйте нужные схемы в JSON из старого интерфейса. После установки импортируйте JSON в новый проект.

## Вариант 1. Сборка из исходников

Загрузите kdfp-trench-network-v7.3.0-source.zip в домашнюю папку сервера. Для сборки нужны доступ к Docker Hub и PyPI. На том же сервере и в прежней папке:

```sh
mkdir -p ~/trench
cd ~/trench
unzip -o ~/kdfp-trench-network-v7.3.0-source.zip
docker compose up -d --build --wait --wait-timeout 120
docker compose ps
curl -fsS http://127.3.0.1:8086/api/health
```

Открыть http://IP-СЕРВЕРА:8086/. Оба контейнера должны стать healthy. Если Docker сообщает TLS handshake timeout при загрузке базового образа, используйте вариант 2.

## Вариант 2. Готовые образы без Docker Hub

Архив kdfp-trench-network-v7.3.0-offline.zip содержит оба образа для Linux amd64 и Compose без сборки/загрузки из реестра. Загрузите архив в домашнюю папку сервера:

```sh
mkdir -p ~/trench
cd ~/trench
unzip -o ~/kdfp-trench-network-v7.3.0-offline.zip
sha256sum -c image.sha256
docker load -i trench-calculator-image.tar
docker compose up -d --no-build --pull never --wait --wait-timeout 120
docker compose ps
curl -fsS http://127.3.0.1:8086/api/health
```

Не добавляйте --build к offline-комплекту. Для сервера другой архитектуры используйте сборку исходников. Сами исходники не содержат пользовательских проектов, локальных черновиков или базы. При первом запуске БД пустая; при обновлении подключается прежний том.

## Порт и обслуживание

По умолчанию порт 8086. Для другого порта задайте PORT=8090 в .env, сохранив остальные существующие строки, затем повторите команду запуска. В curl и адресе браузера подставьте выбранный порт. Домен/HTTPS можно направить на этот порт через существующий обратный прокси.

```sh
docker compose logs --tail=100
docker compose restart
docker compose stop
```

Проверки: /healthz — Nginx, /api/health — API и доступность БД. Обновление не меняет геометрию схем. После замены версии обновите страницу браузера, при необходимости Ctrl+F5. Том переживает пересоздание контейнеров и обычный down. Не используйте down -v, если данные нужны.

## Перенос проектов с этого компьютера на новый сервер

Для отдельных схем используйте экспорт/импорт JSON. Для переноса всей базы: выполните python backup.py внутри локального API-контейнера, скопируйте напечатанный файл через docker compose cp и перенесите его на сервер. Сам Docker-архив БД не содержит. Копия через SQLite Backup API согласована и допускает работающий сервер; копировать только основной .sqlite3 при работающей БД нельзя из-за WAL.

## Восстановление или перенос всей БД

Сначала сохраните текущую БД, если в ней есть нужные проекты. Положите выбранную копию под именем trench-backup.sqlite3 в папку установки. Следующие команды намеренно заменяют серверную БД целиком, а не объединяют проекты:

```sh
cd ~/trench
docker compose stop
docker compose run --rm --no-deps --user root -v "$PWD/trench-backup.sqlite3:/restore.sqlite3:ro" api python -c "import shutil,pathlib,os; p=pathlib.Path('/data/trench.sqlite3'); shutil.copyfile('/restore.sqlite3',p); p.chmod(0o600); os.chown(p,1000,1000); [f.unlink(missing_ok=True) for f in [pathlib.Path(str(p)+'-wal'),pathlib.Path(str(p)+'-shm')]]"
docker compose up -d --no-build --pull never --wait --wait-timeout 120
```

## Откат

Сохраняйте предыдущий архив/образы и compose.before-update.yaml вместе с резервной копией БД. Для возврата к предыдущему интерфейсу загрузите предыдущие образы и восстановите прежний Compose, сохраняя имя проекта и том. Версии 4.1–4.5.0 используют прежнюю схему БД; изменения от более поздних версий не переносите без проверки формата. Откат к статической версии 4.0 требует предварительного экспорта новых схем в JSON.


## Обновление 4.4.1 → 4.5.0: обязательная резервная копия

Перед заменой Compose выполните резервирование из раздела выше и сохраните прежние образы/Compose. API 1.2.0 автоматически обновляет БД до схемы 2, сохраняя модели. Новые поля архива и корзины не поддерживаются API 1.1.0: откат обоих контейнеров к 4.4.1 требует восстановления БД из копии до миграции. Не запускайте старый API на обновлённой БД. Восстановление прежней копии отменяет изменения после её создания — сначала сохраните актуальную БД и экспортируйте нужные новые схемы. Обычное обновление вперёд не требует восстановления БД.

В проекте доступны архив и корзина. Окончательное удаление требует точного названия и удаляет версии схем; для восстановления после него нужна внешняя резервная копия. Настройте принятую у вас процедуру регулярного резервирования.


## Обновление до 5.0.0

В комплекте web 5.0.0 и API 2.0.0. Обновляйте оба контейнера. Таблицы SQLite не меняются (схема 2), модели получают JSON 4 при редактировании. Сделайте резервную копию БД перед обновлением. Откат к API 1.2.0 требует прежней БД: новые модели JSON 4 им не поддерживаются. Запуск и offline-команды выше актуальны для 5.0.0.


Версия 5.1.0: web 5.1.0 + прежний API 2.0.0; формат JSON 4 и схема SQLite 2 не меняются. Добавлены углы выхода трубы, поворот квадратных колодцев с шагом 90° и оси в 3D. Обновляйте по актуальному архиву 5.1.0.


Версия 5.2.0: web 5.2.0 + API 2.0.0. Нужны оба прежних сервиса; схема БД не меняется. Новая проверка прямоугольных подключений может выявить косые входы старых схем — исправьте их выбором стены. Перед обновлением сохраняйте БД.


Версия 5.3.0: web 5.3.0 + API 2.1.0. Обновите оба контейнера, предварительно сохранив БД. Схема SQLite остаётся 2, JSON — 4; добавлены привязки стен и автоматические подводы. Для полного отката используйте сохранённый комплект 5.2.0 и копию БД до обновления.


Версия 5.4.0: web 5.4.0 + API 2.1.0, схема SQLite 2. Перед обновлением сделайте копию БД. Старые автоматические изгибы удаляются при открытии схемы; ручные вершины сохраняются до явного выпрямления. Для отката сохранён комплект 5.3.0 и БД до обновления.


Версия 5.5.0: web 5.5.0 + API 2.1.0. Схема БД не меняется. Добавлены список недостающих грунтов с глубинами и отделение ограничений общей выемки от ошибок ввода. Данные проектов автоматически не заполняются.


Версия 7.3.0: web 7.3.0 + API 2.1.0. Добавлен расчёт общей выемки траншей; итоговые объёмы пересекающихся схем изменятся за счёт устранения двойного счёта. Схема БД и JSON не меняются, миграция данных не нужна. Сделайте резервную копию БД перед обновлением. Пересечения самих котлованов остаются ограничением.


Версия 7.3.0: web 7.3.0 + API 2.2.0. Обновляйте оба сервиса. Схема SQLite остаётся 2, формат модели JSON 4; добавлены необязательные настройки материала засыпки и явной рабочей части. Старый UI их не учитывает: для отката после редактирования высот используйте резервную копию до обновления. Архив не содержит БД.
